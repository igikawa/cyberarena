# CYBERARENA

Локальная учебная CTF-платформа для небольшого турнира: FastAPI, Jinja2, PostgreSQL, SQLAlchemy 2 и Alembic. Участники регистрируются, решают задания, отправляют флаги и видят рейтинг; администратор управляет заданиями и результатами.

## Архитектура

Compose запускает четыре сервиса:

| Сервис | Назначение |
| --- | --- |
| `nginx` | Единственная точка входа, опубликованная на `127.0.0.1:8080`; направляет сайт в `app`, а `/lab/` — в `lab-web`. |
| `app` | FastAPI, Jinja2, серверные формы, API, Argon2id, HMAC-хеши флагов и сессии. Перед запуском применяет Alembic-миграции и идемпотентно создаёт стартовые данные. |
| `db` | PostgreSQL с именованным постоянным volume; порт на хост не публикуется. |
| `lab-web` | Изолированное приложение WEB-01 с намеренной ошибкой IDOR и только синтетическими записями. |

`app` и `db` находятся во внутренней сети `app-net`, лаборатория — только во внутренней сети `lab-net`. Nginx подключён к обеим сетям для HTTP-проксирования, но блокирует запросы из подсети лаборатории ко всем маршрутам платформы; в обратном направлении доступны только явно настроенные маршруты лаборатории. Для публикации host-порта Docker Nginx также подключён к отдельной bridge-сети `edge-net`; masquerading в ней отключён, в сети нет других сервисов, а опубликованный порт привязан только к loopback хоста. Сети `app-net` и `lab-net` помечены `internal`, поэтому приложение, БД и лаборатория не имеют обычного исходящего доступа в интернет. Контейнер лаборатории не видит БД, исходный код платформы, секреты приложения, хостовые каталоги или Docker Socket.

## Требования

- Docker Engine с Compose v2 (`docker compose`).
- Свободный локальный порт 8080.

## Первоначальная настройка и запуск

```sh
cp .env.example .env
```

Замените все `CHANGE_ME` в `.env`. Секреты должны быть уникальными; для Unix-систем их можно сгенерировать командами:

```sh
openssl rand -hex 32   # POSTGRES_PASSWORD
openssl rand -hex 32   # SECRET_KEY
openssl rand -hex 32   # FLAG_HMAC_KEY — отдельное значение
openssl rand -hex 24   # ADMIN_PASSWORD
```

Задайте сгенерированные значения в соответствующих переменных. `ADMIN_USERNAME` задаёт начальный логин администратора. Не добавляйте `.env` в Git и не используйте пароль из примера. После настройки запустите:

```sh
docker compose up -d --build
```

Схема БД обновляется командой `alembic upgrade head` при запуске приложения; приложение начинает работу после успешных миграций и готовности PostgreSQL. При первом запуске создаются учётная запись администратора и три задания. Последующие старты не меняют уже созданные задания и данные администратора, включая сделанные администратором изменения.

- Сайт: <http://localhost:8080/>
- WEB-01: <http://localhost:8080/lab/>
- Локальная документация API: <http://localhost:8080/docs>

Для HTTPS-прокси за пределами этой локальной конфигурации установите `COOKIE_SECURE=true`. Swagger предназначен для локальной разработки; изменяющие API-запросы защищены авторизацией и CSRF.

## Турнир и задания

1. Войдите по `ADMIN_USERNAME` и `ADMIN_PASSWORD`.
2. Убедитесь, что три стартовых задания опубликованы; создайте или отредактируйте задания через **Админка → Задания**.
3. Участники создают аккаунты через **Регистрация**, решают задачу и отправляют флаг на её странице.
4. Текущий рейтинг доступен по ссылке **Рейтинг**. За каждую задачу баллы начисляются одному участнику только за первое правильное решение; повторная отправка не меняет счёт.

Стартовый комплект:

| Задание | Категория / баллы | Механика |
| --- | --- | --- |
| WEB-01 — Скрытый документ | Web / 100 | В отдельной лаборатории найдите документ по чужому ID; ресурс доступен через `/lab/`. |
| WEB-02 — Посмотри исходник | Web / 150 | Исследуйте HTML и локальный JavaScript по ссылке из задания. |
| CRYPTO-01 — Три шага назад | Crypto / 150 | Расшифруйте локально скачиваемый текст шифром Цезаря. |

Правильные ответы хранятся в БД только в виде HMAC с отдельным `FLAG_HMAC_KEY`; API участника не возвращает ни ответ, ни его хеш. Авторские write-up лежат в `docs/writeups/` и не копируются в образы приложения и лаборатории, не подключены к статическому каталогу и не доступны участникам через сайт.

## Администрирование

Админ-панель: `/admin`. Она позволяет создавать, редактировать, публиковать, скрывать и удалять задания. Удаление задания с историей попыток/решений отклоняется с понятным сообщением, чтобы не терять связанную историю. В панели также доступны все попытки, решения и рейтинг.

**Сброс демонстрационного турнира:** `/admin` → «Сбросить результаты» и подтвердить действие. Удаляются только попытки и решения; пользователи и задания остаются. Изменение опубликованности или стоимости задания влияет на его доступность и текущий расчёт рейтинга.

## Эксплуатация и данные

```sh
docker compose ps
docker compose logs -f app db nginx lab-web
docker compose stop
docker compose start
docker compose up -d --build
```

Данные PostgreSQL хранятся в volume `cyberarena-postgres-data` и сохраняются при остановке и пересборке контейнеров. Пример резервного копирования:

```sh
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > cyberarena-backup.sql
```

Полное удаление демонстрационной БД и всех её данных:

```sh
docker compose down -v
```

**Предупреждение:** команда удаляет именованный volume PostgreSQL без возможности восстановления, если нет резервной копии. Не используйте её для обычного обновления приложения; миграции применяются автоматически.

## Локальная разработка и тесты

Нужны Python 3.12+ и отдельная PostgreSQL-БД. Задайте переменные окружения согласно `.env.example`. Если используете `.env` в shell:

```sh
set -a
. ./.env
set +a
```

Установите зависимости, затем:

```sh
pip install -r requirements.txt
alembic upgrade head
uvicorn app.platform.main:app --reload
```

Запуск тестов:

```sh
pytest -q
```

По умолчанию тесты используют отдельный случайный временный SQLite-файл и не подключаются к рабочему Compose volume. Полный concurrency-набор выполняется на PostgreSQL, если явно задать `CYBERARENA_TEST_DATABASE_URL` на отдельную тестовую БД с именем `cyberarena_test*`; тестовый harness удаляет и пересоздаёт таблицы в этой БД. Продакшен/Compose используют PostgreSQL; схема создаётся и обновляется только миграциями Alembic. Применить миграции вручную в запущенном окружении можно так:

```sh
docker compose exec app alembic upgrade head
```

## Ограничения безопасности

Это локальная учебная платформа, а не готовый публичный хостинг. Намеренная IDOR-уязвимость существует только в лаборатории WEB-01 и использует вымышленные данные; не расширяйте её на платформу. Не публикуйте лабораторию или сайт в интернет без отдельного аудита, TLS, резервного копирования и усиления инфраструктуры. Доступ к Docker daemon и права администратора хоста остаются доверенными. `COOKIE_SECURE=false` предназначен для локального HTTP; при HTTPS cookie следует сделать `Secure`.
